# Local Petitions Service (Сервіс електронних петицій)

Веб-сервіс та REST API місцевих електронних петицій з рольовою моделлю доступу (RBAC), JWT-автентифікацією, захистом від атак IDOR та інтерактивним інтерфейсом користувача.

Розроблено в рамках **Лабораторної роботи №2**: *«Користувачі, ролі користувачів та розмежування прав доступу»*.

---

## 📌 Ключові можливості проєкту

- **Автентифікація та авторизація**:
  - Безпечне збереження паролів з криптографічним хешуванням **Bcrypt** (Passlib).
  - Генерація та валідація безсесійних токенів **JWT (HS256)**.
  - Рольова модель **RBAC**: підтримка ролей `user` (звичайний громадянин) та `admin` (адміністратор системи).
- **Контроль доступу та безпека**:
  - **Захист від анонімного доступу**: повернення `401 Unauthorized` для неавторизованих спроб доступу до приватних ендпоінтів.
  - **Вертикальне розмежування**: блокування доступу користувачів до адмін-панелі та модерації зі статусом `403 Forbidden`.
  - **Горизонтальне розмежування (IDOR Protection)**: користувач може редагувати лише власні петиції та власний профіль; спроба модифікації чужих даних повертає `403 Forbidden`.
- **Бізнес-логіка (MVP)**:
  - Створення, перегляд та редагування петицій.
  - Пошук за ключовими словами та фільтрація за статусами (`active`, `under_review`, `approved`, `rejected`).
  - Підписання петицій із контролем унікальності голосу (захист від накрутки голосів).
  - Адміністративна статистика системи та панель модерації.
- **Сучасний інтерактивний UI**:
  - Адаптивний веб-інтерфейс із переглядом каталогу, кабінетом користувача, адмін-панеллю.
  - **Інтерактивний стенд безпеки (Security Playground)** для тестування та демонстрації сценаріїв 401/403/IDOR в один клік під час захисту.

## 🚀 Швидкий запуск

### 1. Активація віртуального оточення
```powershell
.\venv\Scripts\activate
```

### 2. Встановлення залежностей
```bash
pip install -r requirements.txt
```

### 3. Ініціалізація та початкове наповнення бази даних
```bash
python -m src.init_db
```

### 4. Запуск сервера застосунку
```bash
uvicorn src.main:app --reload --host 127.0.0.1 --port 8000
```

Після запуску відкрийте в браузері:
- **Веб-інтерфейс системи**: [http://localhost:8000/](http://localhost:8000/)
- **Інтерактивна документація Swagger**: [http://localhost:8000/docs](http://localhost:8000/docs)
- **Альтернативна документація ReDoc**: [http://localhost:8000/redoc](http://localhost:8000/redoc)

## 🧪 Запуск автоматизованих тестів (Pytest)

Проєкт містить повний набір юніт- та інтеграційних тестів, які покривають усі вимоги лабораторної роботи:

```bash
pytest -v
```

### Сценарії, які перевіряються тестами:
1. **Анонімний доступ**: перевірка повернення `401 Unauthorized` на спроби доступу без токена.
2. **Автентифікація**: успішний вхід (`200 OK` + JWT), відмова при невірному паролі (`401`), відмова при неіснуючому логіні (`401`).
3. **Вертикальне розмежування (RBAC)**: блокування звичайного користувача при спробі відкрити `/admin/dashboard`, `/admin/stats` або змінити статус петиції (`403 Forbidden`).
4. **Горизонтальне розмежування (IDOR)**: блокування користувача при спробі модифікувати чужу петицію або чужий профіль (`403 Forbidden`).
5. **Бізнес-логіка петицій**: створення, перевірка лічильника підписів та блокування спроби повторного голосування (`400 Bad Request`).
